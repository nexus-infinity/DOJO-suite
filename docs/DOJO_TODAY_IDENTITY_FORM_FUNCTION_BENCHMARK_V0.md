## Why this sheet exists

Today already has panel-level “looks like ChatGPT/Claude/Codex” notes. Those are **form** hints. They are not identity, and they are not a complete function bar.

This sitting locks three pins so later work cannot collapse them:

```text
Identity  —  what Today is, and what it must not become
```

A commercial app may win on form and still fail identity. A native loop may be complete and still fail form. Production is only claimed when all three pins are witnessed, not when one vendor screenshot looks similar.

## 3. Function — what one session must complete

The practical bar, already seated in the 2026-08-30 native reconciliation:

```text
one clear intention
→ native input
→ truthful progress
→ first-class object
→ review or continue
→ return to prior work
```

Multimodal means text, file, and voice are **separately usable and separately honest**. It does not mean one processing pipe.

| Function | Benchmark class | Today now |

**Function anti-pattern:** do not make Today a Codex-style agent cockpit, a Warp-style PTY agent, or a Cursor-style multi-file editor in order to “match the market.” Those are different product classes. Terminal sessions stay in Labs / Developer Space (`MACWARP_SALVAGE_MAPPING_V0`).

## 4. Vendor architectures — comparison, not templates

Codex, Warp, and Cursor are **three different product classes**. Mixing any of them into Today is how the application would accidentally become an agent IDE, a GPU terminal, or a VS Code fork.

### 4.1 Codex the shipped desktop product

**Use for:** form class of a desktop AI workspace (rails, composer, preview, tools).
**Do not use for:** DOJO process architecture.

Reported third-party reverse engineering (not opened in this FIELD sitting) describes a layered client:

| Reported Codex client layer | Product role | DOJO translation | Must not become |
|---|---|---|---|
| Frontend UI (Electron / Chromium / Owl, Radix / Lexical or ProseMirror) | Window chrome + editor | Native SwiftUI Today | Electron or web-shell rewrite |
| Local app server / CLI bridge | Restricted OS tasks, git, event stream | Existing Swift clients, local object store, chamber routes | A second “Codex app server” inside DOJO |
| OS automation / accessibility / Computer Use | Screen and click control | HAL + explicit human consent later | Silent screen-scraping as Today |

Evidence status for that client split: `DELAYED` / third-party. Official public object is only “Codex has a desktop app.” FIELD has not reverse-engineered `/Applications/Codex.app` here.

### 4.2 Codex as Apple-application engineer

**Use for:** how an Apple app should be built, not how Today should look.

| Pattern | Purpose | DOJO now |
|---|---|---|
| SwiftUI | declarative native UI | **In use** — Today is SwiftUI |
| CLI-first build (`xcodebuild` / Package.swift) | compile, test, run without GUI fighting | **Partial** — SPM + Xcode project exist |
| App Intents | Siri, Shortcuts, later CarPlay-safe actions | **HOLD** — no App Intents surface yet |
| Documentation-first native APIs | semantic toolbars, not fake frames | **Adopt as a form rule** |

That second table is the only Codex architecture Today is allowed to **imitate**. The first table is a **rival product**, not a template.

### 4.3 Three agent paradigms — none of them is Today

Reported industry split (DELAYED / third-party; not reverse-engineered in this FIELD sitting):

| Paradigm | Specimen | What it optimises | Today relationship |
|---|---|---|---|
| Cloud-sandbox agent | Codex desktop | Delegate a task and walk away in an isolated VM | Rival product. Form only (rails/composer/preview). No sandbox factory. |
| Terminal-native agent | Warp | Command blocks, PTY, interactive shell, GPU text grid | Rival product. Salvage **objects and continuity** from MacWarp map. No WarpUI, no PTY as Today. |
| Editor-native agent | Cursor | Live authoring beside the user: Monaco, Composer, LSP, git index | Rival **editor**, not the application. This sitting happens *in* Cursor; Today must not become Cursor. |

```text
Codex  →  cloud sandbox / delegate
Warp   →  terminal / PTY / blocks
Cursor →  editor / Composer / LSP
Today  →  ordinary native Mac work surface
```

Those four identities must stay separate. Morphosis may change Today’s form. It may not fold Today into a terminal, an IDE, or a sandbox agent.

#### Warp — what may be learned, what must not be copied

| Reported Warp layer | Product role | Lawful Today translation | Must not become |
|---|---|---|---|
| Rust + WarpUI (Metal/Vulkan, custom widgets) | Low-latency terminal chrome | Native SwiftUI semantic windows | Custom GPU UI that bypasses AppKit/SwiftUI |
| Atomic Blocks (prompt + input + output) | Parse one command without stream drift | Generated object = one bounded unit of work | Terminal log as the workspace |
| PTY multiplexing / Agent CLI | Live sqlite3, gdb, REPL | Labs / G6 / Developer Space only | Ordinary Today shell execution |
| Warp Drive / Factories / Foreman | Cloud multi-agent orchestration | Chamber routes and receipts, when admitted | A second cloud factory inside the app |

MacWarp salvage already locked this: Keep intent→object and session continuity. Do not rebuild MacWarp. Do not expose terminal as Today.

#### Cursor — what may be learned, what must not be copied

| Reported Cursor layer | Product role | Lawful Today translation | Must not become |
|---|---|---|---|
| VS Code fork + Electron + Monaco | Editor chrome, inline diffs | SwiftUI canvas + object review | Fork VS Code as DOJO Today |
| Composer + multi-file state | Authoring with LSP/diagnostics | One selected object + continue | IDE-priority tree as first screen |
| Local index / git hash graph | Massive-codebase search | Local object store + proof | Silent whole-workspace ingest |
| Agent Client Protocol | Background agents across IDEs | Separate editor lane; not Today | Treat Cursor protocol as FIELD truth |

Cursor is an invited **editor client** of FIELD. It is not the DOJO application genotype.
