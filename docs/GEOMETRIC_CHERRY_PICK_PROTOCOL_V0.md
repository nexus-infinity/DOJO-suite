# Geometric Cherry Pick Protocol v0

Date: 2026-07-21

## Core correction

Discovery is not placement.
Path is not seat.
Frequency label is not chamber PROMOTE.
When found is not when it fits.
Runtime convenience is not residence.

Cherry-pick means:
name the hole first → pose its harmonic questions → DNA only → score PASS / WEAK / FAIL / UNKNOWN → verdict for that hole only → residence check → receipt.

## Morphosis gate

Morphosis is the gate, not nostalgia and not dig date.

Sequence:
Architecture → House → contracts → suites → candidates → receipts → PROMOTE / HOLD.

No “try it in Ollama first.”

## Residence wireframe

Registry / DNA:
FIELD inventory + chamber configs.

House mirror:
`/Users/field/models/...`
sovereign pull-down / managed mirror.

Archive:
Akron hexagon dump or other archive store.
Filesystem archive ≠ chamber AKRON.

Runtime guest:
`~/.ollama`, MLX cache, vendor cache, or engine cache.
Guest bind only.
Not sovereign home.

## Pick sequence P0-P6

P0 — Name the hole:
one matrix row or one chamber contract.

P1 — Pose the hole’s questions:
use ecosystem matrix, Morphosis contracts, and chamber contract questions.

P2 — DNA only:
path, size, base, labels, claims.
No forced load.

P3 — Score:
PASS / WEAK / FAIL / UNKNOWN per question.

P4 — Verdict for that hole only:
PROMOTE.candidate
HOLD.Unknown.Placement
HOLD.Wrong.Slot
DEMOTE.slot_claim
ARCHIVE.only

P5 — Residence check:
Is there a draft residence?
Is RESIDENCE.LOCKED present?
Is runtime only guest-bound?
If no, HOLD.RuntimeSplit.

P6 — Receipt:
state candidate, hole, evidence, residence, verdict, non-claims.
